# immich-remix — Design decisions

Oct 21, 2026

[docs/spec.md](../../spec.md) is the full product and technical spec and is the source of truth. This document records the decisions made while reviewing it, and every place they change or settle the spec. Where the two disagree, this document wins.

## Intent

A Google Photos Remix for the owner's own Immich library: pick a photo or video on a phone, pick a style by its picture, get a restyled copy saved back to Immich stacked next to the original. Everything in spec.md is v1. Nothing is deferred to a later phase except where noted below.

## Decisions (from the owner)

1. **Scope:** all of spec.md is v1: all six providers, video, 44 built-in styles, Custom, the preview generator.
2. **Style previews are representative, not a shared reference.** Each built-in style's preview is an image generated from the style itself (text-to-image), showing what that style looks like. There is no reference photo or reference clip, so nothing needs to be created or licensed.
3. **Test target:** the owner's Immich at `http://192.168.1.20:2283`, version 3.3.1, on the local network. A scoped API key exists in the project's `.env`.
4. **Available backend for live testing:** Google Gemini ("Nano Banana") only. The key is in `.env`.
5. **Default photo model is Nano Banana 2**, and the model can be changed later in Settings from a dropdown filled by the provider. See *Smaller gaps settled*.

## Builder's calls (confirmed with the owner by silence; flag if wrong)

- **Single user**, one Immich API key. All saves go to that account.
- **Stack primary:** the original stays primary by default. This stays a setting as spec.md describes.
- **No upscaling.** Outputs are saved at whatever resolution the backend returns.
- **Cost estimate is shown** for cloud backends, using the existing `cost_estimate_usd` fields. Prices live in config with documented defaults.
- **Long videos: trim only in v1.** The trimmer limits the clip to the backend's maximum. Segmented remixing (`segmentable`, split/join, the drift warning, `jobs.segmented`) is not built. Keep the `segmentable` key accepted-and-ignored in style YAML so files stay forward compatible.
- **Style editing in Settings is a form**, not a YAML editor. The fields are: name, category, media types, prompt, negative prompt, strength, default backend per media type, and preview (generate or upload). Saving writes a YAML file to `/data/styles/`. Per-provider overrides (`providers:`) are editable only by hand in the YAML file.

## Changes to spec.md

### Previews

Replaces the "One reference set" and related parts of *Style previews*.

- Each built-in style ships one still preview, generated by text-to-image from a per-style **preview prompt** (a new YAML field `preview_prompt`): a representative scene (a person outdoors, face visible, some background) rendered in that style. Files are WebP, 600 × 600 for cards and 1600 px long edge for the full view, bundled under `/app/styles/previews/`.
- **No video previews.** Video-capable styles use the same still preview. The `preview.video` YAML key, the looping card behaviour and `styles.preview_video_path` are dropped. The card still gets the accent ring when selected.
- **Full-screen preview** (long-press or the info icon) shows the preview image full screen. The before/after slider against a reference is dropped, since there is no reference.
- **Custom styles:** "generate preview" runs text-to-image from the style's prompt, or its `preview_prompt` if set, on the style's default photo backend. The estimated cost is shown first. Upload is still offered. The placeholder until then is unchanged.
- **Provider interface:** add an optional text-to-image capability, used only for previews: `async def generate(self, prompt: str) -> bytes`, with a `can_generate: bool` flag. Gemini and OpenAI implement it, and Stability and ComfyUI may. If no enabled backend can generate, the button is hidden and upload is the only option.
- `scripts/build_previews.py` generates all built-in previews with Gemini (`gemini-3.1-flash-image`). The builder runs it once during the build, using the owner's key, and commits the outputs.

### Configuration names

- The app reads the names in spec.md: `IMMICH_API_KEY` and `GEMINI_API_KEY`. The owner's local `.env` currently uses `IMMICH_KEY` and `GOOGLE_KEY`. The builder renames those two lines in `.env`, which the owner allowed for this purpose, and adds no aliases.
- `.env` goes in `.gitignore` and `.dockerignore`. It is used for local development and `docker run --env-file`.

### Verified against the live server (v3.3.1)

Every endpoint in spec.md's *Calls used* table exists. `SmartSearchDto` and `MetadataSearchDto` both accept `personIds`, `city`, `state`, `country`, `takenAfter`, `takenBefore`, `type`, `page` and `size`. `AssetBulkUpdateDto` (`PUT /api/assets`) accepts `dateTimeOriginal`, `latitude`, `longitude`, `description` and `timeZone`. `StackCreateDto` takes `assetIds`.

There is no separate search permission. Search falls under the asset permissions. These are the exact permission names for the README:

`asset.read`, `asset.view`, `asset.download`, `asset.upload`, `asset.update`, `person.read`, `album.read`, `album.create`, `albumAsset.create`, `stack.create`, `stack.read`, `stack.update`, `tag.read`, `tag.create`, `tag.asset`, `user.read`, `server.about`.

The library is large: 1,838 people and 477 cities. The People row pages through results and shows named people first. The Places list filters on the server side by text and never renders everything.

The build rule from spec.md still applies: generate or verify the Immich client against `GET /api/spec.json` from this server.

### Smaller gaps settled

- **Photo input quality:** the default is the original (`/assets/{id}/original`), converted and resized as spec.md describes. RAW files use the preview. A setting under *Photo output* offers "Send original" or "Send preview".
- **Plain HTTP on the LAN** (owner's call). The app ships no TLS. The session cookie is HTTP-only with `SameSite=Lax`, and gets `Secure` only when the request arrived over HTTPS. The service worker registers only where the browser allows it, and the app works fine without it. Acceptance changes: on iPhone, "Add to Home Screen" opens full screen. On Android over plain HTTP, a browser shortcut is acceptable. The README notes that putting HTTPS in front, for example with `tailscale serve`, gives Android the full app install.
- **Immich v3 only** (builder's call). The client is generated from v3.3.1's `spec.json`. On startup the app refuses servers older than 3.0 and shows a clear banner. This replaces "targets Immich v2 and v3" in spec.md, because there's no v2 server to test against.
- **Environment values versus Settings:** a value set by environment variable shows in Settings as "Set by environment" and is read-only.
- **Model defaults:** Gemini defaults to `gemini-3.1-flash-image`, which Google lists as "Nano Banana 2"; the owner chose it. Other providers' defaults come from their current docs at build time, as spec.md says.
- **Model picker (owner's request):** in Settings, each backend's model is a dropdown filled from that provider's own model list. The provider interface gets `async def list_models(self) -> list[ModelInfo]`, where `ModelInfo` has `id`, `label` and `media_types`. Gemini reads `GET /v1beta/models` and keeps the models whose names contain `image`, labelled with their display names (for example "Nano Banana 2 · gemini-3.1-flash-image"). Providers that have no listing API, or whose listing call fails, fall back to a free-text field that shows the configured default. The chosen model is stored in settings and passed to every call.

## Testing

- **Live:** Immich read paths. The live write-path test uses no real photos. It first uploads its own synthetic "original" (a generated JPEG with a set date and GPS), then remixes that with Gemini, saves the result, and stacks it with the synthetic original. Both go into a `Remixes-test` album. The key has no `asset.delete`, so the test can't clean up after itself: the README and the test output tell the owner to trash that album's assets by hand. "Original untouched" means its checksum, date and GPS are the same before and after. Stack membership is left out of that check, because stacking changes it by design. Preview generation runs live too.
- **Mocked only:** OpenAI, Stability, Runway, Luma and ComfyUI, with HTTP mocked from each provider's current API docs. Nobody has a key or server for these, so the owner's first real use is their first live test. The README says so.
- The unit test list in spec.md's acceptance criteria stands, minus segmenting.

## Left to the builder
